# Claude 전달용 — 둘러보기·공고 상세·비로그인 별칭 통합 수정

> 현재 기획 기준: [PRD](../../planning/requirements/PRD.md) → [IA](../../planning/design/IA.md) → [유저플로우](../../planning/design/USER_FLOW.md). 성인 여성만 가입·이용하며 동행은 양측이 확정한다. 아래 과거 기록의 남성 가입·S07·성별 필터·작성자 단독 확정 설명은 현재 요구사항으로 사용하지 않는다.

작성: 2026-09-20. 상태: **사용자 요청을 통합한 실행 프롬프트 / HTML 수정 전**.
> 2026-09-21 후속: 이 상태는 작성 당시 기록이다. HTML 인수인계에 4차 수정까지 기록돼 있으며 후속 작업은 [안티그래비티 이관 프롬프트](ANTIGRAVITY_WIREFRAME_CONTINUE_2026-09-21.md)를 사용한다. 아래 초기 요구를 전부 재실행해 후속 사용자 수정을 되돌리지 않는다.

이 파일 전체를 원본 HTML을 만든 Claude 대화에 전달한다. 접근 가능한 작업 폴더를 사용하되 웹 채팅에서 로컬 파일을 읽을 수 없다면 필요한 파일과 레퍼런스를 첨부받는다.

---

너는 기존 유미당 와이어프레임 HTML을 만든 담당자다. 아래 요구사항을 반영해 기존 HTML을 수정해줘. 이번 목적은 포트폴리오 준비와 팀 화면 구조 검토다. 완성 화면만큼 수정 이유·권한·상태가 명확해야 한다.

이번 사용자의 명시적 수정은 이전 Stitch 프롬프트보다 우선한다. 미확정·GPT 제안은 확정으로 바꾸지 않는다. 기존 24개 주요 화면 ID·검토 도구·관련 없는 화면과 입력 유지 동작을 보존한다. HTML을 처음부터 다른 구조로 다시 만들지 않는다.

단일 HTML과 인수인계만 수정한다. 실제 앱 코드·DB·키·원격 설정·커밋·푸시·배포는 이번 작업에 포함하지 않는다. API 호출 대신 합성 예시로 동작시키고, 실제 연동처럼 설명하지 않는다.

## 2. 동행 둘러보기 S01 — 레퍼런스를 나눠 적용

아래 두 다운로드 폴더 안의 자료를 먼저 열어 확인한다. 한글 파일명 정규화 차이가 있으면 실제 폴더명으로 찾는다.

1. `~/Downloads/동행 둘러보기_동행카드 제외 나머지 부분(상단바+검색창,필터)`
   - 동행카드를 제외한 상단바·검색창·필터 영역의 배치와 형태를 참고한다.
2. `~/Downloads/동행둘러보기_동행공고 카드`
   - 동행 공고 카드의 배치와 형태를 참고한다.

자료에 접근할 수 없다면 어느 자료가 필요한지 알려주고, 확인 가능한 공고 상세 수정은 계속한다. 읽지 않은 레퍼런스를 본 것처럼 재현하지 않는다. 폴더에 대안이 여러 개이고 기준을 특정할 수 없다면 핵심 선택만 질문한다.

필터 진입 버튼만 만들지 말고 **필터가 열린 화면**도 만든다. 레퍼런스의 화면 형태를 따르며 기존 필터의 선택·초기화·적용·닫기와 적용 조건 표시를 연결한다. 적용 전 선택과 적용된 조건을 구분한다. 세부 동작은 검토 가능한 시안으로 제안하고 변경 이유를 적는다.

레퍼런스와 기존 기능 범위가 다르면 새 필터·정렬·지도·성별/나이 접근 권한 등을 자동 추가하지 않는다. 차이를 Q47·UX-FILTER-01 검토 메모로 남긴다. 필터는 S01의 하위 상태로 관리하며 독립 최상위 화면이나 새 탭을 만들지 않는다.

## 3. 공고 상세 S02 — 모든 변형 화면의 공통 변경

기본·비로그인·신청 조건 불일치·작성자·마감 등 **모든 해당 변형**에 일관되게 반영한다. 공통 컴포넌트를 확인해 일부 상태에 옛 문구가 남지 않게 한다.

1. `1/2명 (모집중)` 표시는 `모집중`으로 바꾼다. 다른 상태까지 모집중으로 덮어쓰지 않는다.
2. `연결 행사`는 공고에 행사가 등록된 경우에만 표시한다. 미등록이면 제목·값·빈 컨테이너 전체를 숨긴다. 비로그인에서 등록 행사도 숨길지는 6절의 비교 시안이며 아직 확정하지 않는다.
3. 닫기 X 버튼은 우측 상단으로 통일한다.
4. 다음 안내 블록을 제거한다.
   - `🔒 상세 만남 장소는 1:1 매칭 확정 후 공개됩니다`
   - `지금은 시·구·동까지만 보여요.`
   문구를 제거해도 공개 지역과 비공개 상세 장소의 권한은 유지한다. 정확한 장소는 작성자·확정 상대만 볼 수 있고, 비로그인·미확정 신청자에게 공개하지 않는다.

## 4. 공고 상세 — 역할·상태별 변경

### 신청 조건 불일치

- 위 상세 장소 안내 블록을 제거한다.
- `이 공고는 여성 회원만 신청할 수 있어요.` 문장을 제거한다.
- 신청 자격 판단과 신청 불가 상태는 유지한다. 성별 제한을 없애거나 신청 버튼을 활성화하는 요구가 아니다. 기존 조건 정보 자체를 일괄 제거하지 않는다.

### 공고 작성자

- 기존 `공고 수정` 텍스트 버튼 대신 우측 상단 X **왼쪽**에 수정 아이콘을 배치한다. 접근성 이름은 `공고 수정`, 충분한 클릭 영역을 제공한다.
- 작성자만 상단 `모집중` 등 모집 상태를 눌러 상태 메뉴를 열 수 있다. 상태 텍스트 **오른쪽 아래 방향 화살표**로 변경 가능한 요소임을 표시한다.
- 다른 사람에게 상태는 읽기 전용이며 화살표·상태 변경 동작을 제공하지 않는다. 화면의 상태 전환 도구로 작성자 역할을 선택한 경우에만 모형 동작을 보여준다.
- 기존 `모집 조기 마감`은 별도 하단 버튼 대신 상태 메뉴의 기존 허용 동작으로 이동한다. 재모집·확정 후 변경·확정 취소 등 미정인 전환은 추가하지 않는다. 기존 HTML 시나리오에서 확인되지 않는 전환은 화면 밖 검토 메모로 남긴다.
- 하단 버튼 영역에는 `공고 삭제하기`만 배치한다. 기존 삭제 확인·취소 흐름은 유지한다. 아이콘 이동이나 메뉴 변경으로 실제 편집·삭제 허용 조건을 확장하지 않는다.
- 상태 변경 모형에서 관련 배지·신청 가능 상태를 일치시킨다. 일반 회원이 동일 메뉴를 열 수 없게 한다. 실제 서버 권한 검증 완료로 표현하지 않는다.

### 삭제된 공고

기존 안내:
`새 신청은 할 수 없어요. ‘나’와 채팅에서 이전 신청과 대화 기록은 확인할 수 있습니다.`

변경 안내는 정확히:
`새 신청은 할 수 없어요. 채팅에서 이전 기록을 확인할 수 있습니다.`

이는 문구 변경이다. 기록 보존·채팅 접근 권한 변경이나 나 탭의 기존 기능 삭제가 아니다.

## 5. 비로그인 작성자 이름 — 시스템 랜덤 별칭

사용자가 원하는 것은 **닉네임 가입 기능이 아니라, 비로그인 방문자가 이름으로 성별을 추측하고 위치·연결 행사와 결합해 작성자를 특정하기 어렵게 만드는 표시 방식**이다.

- 비로그인 공고 목록·상세와 같은 작성자 표시가 있는 공개 공고 진입에 시스템 별칭을 적용한다. 새 닉네임 입력·수정 화면은 만들지 않는다.
- 검토용 예시: `동행자 4827`. 이름·성별을 암시하지 않는 중립적인 형식으로 만든다. 이는 최종 명명 규칙이 아니라 GPT의 시안 제안이다.
- 시안에서는 같은 공고의 목록·상세에 같은 별칭을 유지하고, 다른 공고까지 동일 작성자로 연결되는 공통 별칭은 사용하지 않는 안을 보여준다. 매 렌더링마다 바뀌어 사용자가 혼동하지 않게 한다.
- 별칭 유지 범위·갱신 주기·방문자별 동일 여부·중복 허용은 ANON-02의 미확정 정책이다. 위 모형의 선택을 서비스 정책으로 확정하지 않는다.
- 실제 사용자/공고 ID나 마스킹 이름을 이어 붙인 값을 랜덤 익명 별칭으로 쓰지 않는다. 합성 시나리오 데이터에만 예시 별칭을 둔다.
- 비로그인 성별·나이 숨김은 유지한다. 로그인 후에는 기존 마스킹 이름 표시를 유지한다. 타인의 공개 프로필 로그인 조건도 유지한다.
- 역할/로그인 상태를 전환할 때 이전 상태의 이름·상세 장소가 남지 않게 시안을 확인한다. 이 모형 확인을 실제 서비스 API의 개인정보 비노출 검증으로 기록하지 않는다.

## 6. 별도 비교 시안 — 아직 결정되지 않은 부분

이름을 가려도 사진·정확한 행사·일정·지역·본문을 조합하면 식별 단서가 남을 수 있다. 다음은 **GPT 제안이며 사용자 확정이 아니다.** 기본 화면의 정책으로 조용히 적용하지 않는다.

- 비로그인 사진을 기본 아바타로 바꾸는 안.
- 등록된 연결 행사를 비로그인에서는 제한하는 안. 제목만 가리고 이미지·링크로 동일 정보가 드러나는 문제도 검토 메모에 적는다.
- 일정·지역·제목/본문의 조합 단서를 어디까지 줄일지의 쟁점. 특정 범위나 시간 단위를 임의로 확정하지 않는다.

기본 수정본과 비교안을 화면 밖 검토 도구에서 구분해 볼 수 있게 한다. 기존 변형 안에 묶고 새 주요 화면 수로 세지 않는다. 사진·행사를 제한한 시안은 ‘공개 범위 비교안 / 팀원 1 결정 대기’로 표시한다. 검토 주석을 실제 앱 문구로 넣지 않는다.

기본 수정본의 ‘행사 등록 시 표시’와 이 비교안의 ‘비로그인 예외 검토’를 구분한다. 상세 장소 권한은 두 안 모두 그대로 지킨다. ‘스토킹 방지 완료’, ‘익명성 보장’이라고 표현하지 않는다.

## 7. 정책·API 변경 기록과 담당 경계

- 주 설계 담당 GPT가 정책·API 인수인계의 통합 담당이다. 이번 Claude 작업은 해당 문서를 읽되 함께 수정하지 않는다.
- 새 충돌을 발견하면 HTML 인수인계에 `발견 / 영향 화면 / 관련 ANON·UX·API ID / 제안 / 결정 대기`로 남긴다. GPT가 팀원 1·2 문서에 반영한다.
- 팀원 1: 익명 공개 기준·별칭 유지 범위·허용 모집 상태 전환을 결정/보류로 회신한다.
- 팀원 2: 화면에서만 가리는 것이 아니라 익명 API 응답의 이름·식별자·사진·행사 정보와 권한·캐시를 확인한다. 외부 닉네임 서비스나 추가 API 키 발급은 요청하지 않는다.
- 기존의 필수 사진, 가입/신청 권한, AI 브리핑 확정 캡션 등 관련 없는 확정 기준은 유지한다.

## 8. 검증과 전달

영향받은 화면과 연결 흐름을 확인한다. 별도 테스트 체계를 만들거나 이전에 통과한 전체 검사를 이유 없이 반복하지 않는다. 이전 담당자의 확인 기록을 이번 실행 결과로 복사하지 않는다.

확인 범위:
- S01: 두 레퍼런스 반영, 필터 열기·선택·초기화·적용·닫기, 적용 조건 표시.
- S02: 비로그인/신청자/조건 불일치/작성자/마감/삭제 상태.
- 연결 행사 있음·없음에서 빈 제목이나 불필요한 여백이 없는지.
- 모든 해당 상태의 옛 모집 문구·장소 안내·성별 사유 문장이 제거됐는지.
- X·수정 아이콘 위치, 작성자 전용 화살표와 메뉴, 하단 삭제 버튼, 확인 취소·뒤로가기.
- 별칭의 같은 공고 내 일관성, 비로그인 성별·나이 숨김, 로그인 전환 시 표시 복구.
- 상태 메뉴 수정 뒤 모집 상태와 신청 동작의 일관성.
- S01→S02→S08→S11 연결 유지와 모바일 잘림·가로 넘침·고정 영역 겹침.
- 기본 수정본과 정책 미정 비교안이 시각적으로 구별되는지.

완료 결과:
1. 수정된 단일 HTML.
2. 기존 HTML 인수인계에 이번 수정 내용·이유·참고한 레퍼런스·미결정 사항 추가. 과거 검사 기록과 이번 기록을 구분한다.
3. 실제 확인한 항목과 미실행 항목. 검증하지 않은 것은 `NOT_RUN`으로 기록한다.
