# 관심친구 — 선택 반영과 알림 검토

현재 사용자 화면: [초대 정렬·설정 선택판](FAVORITE_SORT.html).
**기본 흐름·알림·정렬·설정 대상 선택 완료. 서비스에서는 ‘알림’ 하나로 통일. 2026-09-15에 노션 FAVORITE-01~05와 CHAT-04의 관심친구 참조 메모 한 칸을 최신화했다. 이후 사용자 지시에 따라 이 재정의는 유지하고, N1/N2/S1/S2 및 연결된 F04/F05를 NOTI-01·MY-01·MY-02의 기존 문구 뒤에 기울임꼴로 추가·재조회 검증했다. 앱 구현은 미시작.** [노션 기능명세](https://app.notion.com/p/3d5626093f2e8031927bf5d680bebe67) · [관심친구 변경 기록](notion-favorite-sync.json) · [추가 반영 기록](notion-additions-sync.json)

## 사용자 목적

1. 동행 공고에 신청했지만 확정되지 못해 함께하지 못한 상대를 저장하고, 그 사람이 다음 공고를 올리면 알림을 받는다.
2. 마음에 들었던 과거 동행 상대에게 내가 작성한 공고로 초대할 수 있다.

새 공고 소식은 저장한 사용자가 받는 알림이다. 초대는 초대받은 상대가 받는 알림이다. 인기 사용자에게 초대가 몰릴 수 있다는 우려는 타당한 검토 가설이며 발생량·불편·활성화 효과는 아직 관찰하지 않았다. 사전 제안 방식도 상대에게 요청을 보내므로 그것만으로 부담이 줄어든다고 단정하지 않는다.

## 선택 확정

| 항목 | 결정 |
| --- | --- |
| F01 | 동행 경험 없이 누구나 저장 가능 |
| F01B | 단방향 비공개 저장. 저장 알림은 상대에게 보내지 않음 |
| F02 | 공개 공고 작성 후 초대. 공고 생성 시 전체 공개. 공고 확인 후 직접 신청하고 작성자 최종 수락 시 확정 |
| F04 | 알림에서 대상 공고로 바로 연결 + Me에서 보낸/받은 신청·초대 목록 관리 |
| F04 정렬 | 기본 최신 초대순에서만 관심친구 우선. ‘시간순’은 고정 없이 전체를 동행 시작이 빠른순으로 정렬 |
| F05 | 저장 해제는 목록에서만 제거. 진행 초대·신청·확정 동행은 유지 |

‘관심 있어요’를 먼저 받고 공고를 만드는 기존 문서의 순서는 사용하지 않는다. 공고 알림을 받은 사실과 초대 수신만으로 신청·확정을 생성하지 않는다.

## Me 배치와 시간순 해석

- 기존 상단 신청한 건/신청받은 건 두 탭을 유지하고 초대 관리 진입점을 추가하는 스케치다.
- 최신 초대순에서만 수신자가 저장한 관심친구를 첫 묶음에 둔다. 시간순에서는 묶음과 상단 고정을 사용하지 않는다.
- S1 최신 수정 확정: 기본은 최신 초대순 + 관심친구 우선. ‘시간순’에서는 전체 초대를 동행 시작이 빠른순으로 정렬한다. 관심친구 여부가 시간순 순서에 영향을 주지 않는다.
- 이름 옆 표시는 관심친구 ★, 이전 동행은 ‘동행한 적 있음’, 두 조건에 해당하면 둘 다 표시. 둘 다 해당하지 않으면 표시 없음. 시간순에서 관계를 확인할 수 있도록 한다.
- 과거 동행이라는 이유만으로 상단 고정하지 않는다. 사용자의 관심친구 저장 상태를 기준으로 한다.
- 저장 해제 시 최신 초대순에서는 일반 묶음으로 이동한다. 시간순에서는 시작 시각이 같으므로 위치를 바꾸지 않고 별표만 제거한다. 초대 수신 시각을 갱신하지 않는다.
- 발신자에게 수신자의 저장 여부·상단 고정 여부·조용히 받기 분류를 노출하지 않는다.
- 사례의 이름·시간은 화면 설명용 예시이며 실제 데이터가 아니다.

## N1/N2/S1/S2 확정

- N1 A: 저장 시 새 공고 알림 기본 켜짐, 사람별 끄기 가능.
- N2 B+수정: 모든 초대 알림 기본 켜짐. Me > 설정 > 알림에 **‘처음 보는 사람의 초대 알림’ 스위치 하나**를 제공한다.
- 서비스 UI에서는 푸시/종을 분리해 표시하거나 별도 설정으로 묻지 않는다. 사용자에게는 이름과 켜기/끄기 모두 ‘알림’ 하나로 제공한다.
- 구현 내부에서는 이 한 설정으로 해당 초대의 외부 알림과 앱 알림 생성을 함께 제어한다. 실제 전송 연동은 별도 작업이다.
- 알림을 꺼도 Me 받은 초대는 유지한다. 설정을 껐다고 초대 수신을 거부하거나 이전 기록을 삭제하지 않는다.
- S1: 기본 최신 초대순 + ‘시간순’ 메뉴. 시간순은 그룹 구분 없이 전체 시작 시각 오름차순. 최신 초대순에만 관심친구 우선 적용.
- S2 A: 처음 보는 사람 = **수신자가 저장하지 않았고 실제 동행 경험도 없는 사람**. 두 조건을 모두 충족해야 이 설정의 대상이다.
- 내가 저장한 상대와 과거 동행의 알림은 이 스위치로 꺼지지 않는다. 과거 동행이라는 이유로 받은 초대 상단에 고정하지는 않는다.
- 이전의 푸시·종 개별 스위치 제안과 미선택 A/B 표기는 폐기한다. 예시 조작은 실제 서비스 기본값을 바꾸지 않는다.

사용자 최신 답변: 시간순 배치·관계 표시를 위처럼 수정하고 **나머지 선택은 확정**. 기존 알림 한 개 설정·S2 범위 등은 재질문하지 않는다.

## 이어서 명세화할 경계

- 동일 공고 재초대/철회, 발송량 제한 필요 여부. 이번에 정한 수신 설정 범위는 다시 질문하지 않는다.
- 저장 해제 이후 새 공고 소식의 구독 상태. 저장과 구독을 분리하는 안이면 두 상태를 명확히 표시한다.
- 공고 마감·만료·취소 시 초대의 대상 상태와 신청 CTA, 중복 클릭의 알림 중복 방지.
- 차단/탈퇴/이용 제한 상대의 노출·접근·초대 처리와 기존 기록 유지.
- 위 경계는 선택한 흐름을 기준으로 구체화한다. 기존 문서 전체를 사용자 승인으로 간주하지 않는다.
