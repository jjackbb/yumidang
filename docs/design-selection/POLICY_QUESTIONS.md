# 남은 정책 질문 — 질문과 제안을 구체적으로 관리

현재 상태: **Q1 A, 공개 공고 작성 후 초대, 관심친구 기본 흐름·N1 A·N2 B·S1 A·S2 A 확정. 서비스 알림 설정 하나로 통일. Q3 숫자 묶음 미채택.** [확정 스케치](FAVORITE_SORT.html)에 반영했다. 아래 이전 제안은 기록이며 현재 구현 지시가 아니다.

평가 공개의 확정 규칙: 종료 후 7일까지 작성, 양쪽 모두 제출 시 공개, **7일 뒤 자동 공개는 삭제**. 당도 합산·하한·갱신 시점은 사용자가 별도 논의 항목으로 남기라고 했다.

## 관심친구: 문서에 이미 있는 틀

이번에 재조회한 [기능명세 FAVORITE-01~05](https://app.notion.com/p/3d5626093f2e8031927bf5d680bebe67)에 다음 내용이 있다. 처음에는 문서 기준으로 유지하려 했으나, 사용자가 아직 검토하지 않은 내용임을 확인했다. **아래 내용 역시 승인된 정책이 아니라 항목별 재검토 대상이다.**

- 로그인한 사용자가 동행한 적 없는 상대도 저장할 수 있다.
- 단방향 저장이며 상대에게 저장 사실을 알리지 않는다. 저장 인원 제한 없음.
- 본인·차단·탈퇴·이용 제한 대상과 중복 등록은 제한한다.
- 제안에 일정·동행 유형·간단한 내용을 넣는다. ‘관심 있어요 / 어려워요’로 응답한다.
- ‘관심 있어요’는 동행 확정이 아니다. 정식 공고를 만든다.
- 명세 본문은 공고 확인 후 직접 신청을 요구하며 메모에는 재논의 질문이 있다. 이번 안은 **완성된 공고에 직접 신청 → 작성자 최종 수락**을 유지한다. 관심 표현 시점에는 상세 조건이 확정되지 않았기 때문이다.
- 확정 전 채팅은 기존 신청 이후 흐름을 사용한다. 제안 단계의 별도 채팅을 새로 추가하지 않는다.
- 연락처는 공개하지 않는다. 차단·탈퇴·제한·지난 일정에는 제안/연결을 제한한다.
- 공고의 조건이 바뀌면 기존 조건 재동의 흐름을 유지한다.

## Q1. 평가 7일 규칙 — A 확정

사용자 확정: **본인이 완료 확인하고 평가를 제출해야 상대 평가를 볼 수 있다.** 아래 어느 안도 이 조건을 없애지 않는다.

| 안 | 작성 기한 | 공개 | 고려할 점 |
| --- | --- | --- | --- |
| A — 추천 | 동행 종료 후 7일 | 양쪽 제출 시 공개. 7일 자동 공개 없음 | 한쪽이 끝내 쓰지 않으면 해당 동행 후기가 비공개로 남음 |
| B | 기한 없음 | 양쪽 제출 시 공개. 7일에는 미작성 알림 | 오래 지난 동행의 평가가 뒤늦게 들어올 수 있음 |

추천 근거: A는 작성 기간을 짧게 유지하고 사용자에게 기간을 설명하기 쉽다. 다만 미작성자가 불리한 후기 공개를 막을 수 있다는 한계가 있다. 이런 일이 반복되면 제3자 공개 정책을 별도로 바꿀 근거가 된다. 지금은 간접 열람을 허용하는 우회 경로를 조용히 추가하지 않는다.

## Q2. 공고 공개 범위 — B, 선행 흐름은 재검토

이전 질문이 전제했던 ‘관심 표시 → 공고 등록’은 **사용자가 판단하지 않았던 흐름**이다. 이 전제를 폐기하고 등록·제안·공고의 순서를 다시 비교한다. 작성자 최종 수락이라는 기존 확정 기준은 유지한다.

| 안 | 공개와 전환 | 고려할 점 |
| --- | --- | --- |
| A — 추천 | 친구에게 먼저 6시간 공개. 미신청 시 작성자가 전체 공개로 전환 | 먼저 의사를 확인한 친구에게 기회를 주지만 모집이 늦어질 수 있음 |
| B | 등록 즉시 전체 공개. 친구에게 연결 알림 | 바로 모집할 수 있지만 의향을 밝힌 친구가 다른 후보와 경쟁 |

6시간은 정식 검증된 수치가 아닌 초기 제안이다. 모집 마감·희망 시작을 넘기는 우선 기간을 만들지 않는다. A에서 전체 공개는 자동 전환이 아니라 작성자의 행동으로 제안했다.

## Q3. 이전에 제안했던 관심친구 정책 — 미채택 기록

아래 ①~⑥의 채택을 질문했으나 사용자는 기존 명세부터 재검토하자고 답했다. **전부 현재 구현 지시에서 제외한다.** 특히 구체적인 숫자는 원문이 아닌 AI 제안이다.

| 번호 | 추천 초안 | 대안 / 이유 |
| --- | --- | --- |
| ① 응답 기한 | 발송 후 24시간 또는 희망 시작 시각 중 빠른 때까지 | 48시간은 응답 여유가 늘지만 다음 날 일정엔 늦음 |
| ② 장소 입력 | 제안 때 동네까지, 상세 장소는 공고에서 | 장소 없이 시작하면 가볍지만 거리 판단이 어려움 |
| ③ 발송 제한 | 하루 3건, 월~일 주간 10건 | 제한 없음은 자유롭지만 반복 연락 부담이 큼. 수치는 초기 제안 |
| ④ 저장 해제 | 즐겨찾기만 해제, 진행 제안은 유지. 제안 취소는 별도 | 함께 취소하면 단순 목록 정리가 상대의 약속 의향까지 지움 |
| ⑤ 재발송 | 거절·만료 뒤 동일 상대·동일 일정 재발송 제한 | 즉시 재발송 허용은 정정하기 쉽지만 반복 요청이 될 수 있음 |
| ⑥ 종료 이력 | 종료 제안을 30일 표시 후 보관함으로 이동 | 항상 목록에 두면 찾기는 쉽지만 누적됨. 이동은 데이터 삭제가 아님 |

아래 세부 동작도 당시 제안에 종속된 초안이며, 선택한 새로운 흐름에 맞춰 다시 설계한다:
- 날짜 경계는 서비스 표시 시간대인 한국 시간으로 일치시킨다. 취소된 발송도 발송 횟수에 포함하는 안으로 명세화하고 차이가 있으면 표시한다.
- ‘관심 있어요’를 기한 내 누르면 응답 대기는 끝난다. 이후 공고 등록은 희망 일정이 지나기 전에 가능해야 한다.
- 저장을 해제해도 제안이 남는 안이면 Me의 진행 중 제안에서 계속 볼 수 있게 한다. 친구 목록에서 지워졌다고 제안 접근까지 사라지면 안 된다.
- 공고 등록 후의 취소는 연결 공고/신청/동행 상태와 함께 처리한다. 제안만 취소된 것처럼 표시하지 않는다.
- 실제 외부 발송·보존기간·자동 삭제와 프로토타입의 표시/상태 전환은 구분한다.

## 새 완료 방식 때문에 별도로 답이 필요한 경계 사례

아래는 묵시적으로 확정하지 않는다. Q1~Q3 응답을 받은 다음 한 번에 짧게 확인할 구체적 안이며, 필요하면 사용자가 지금 함께 수정할 수 있다.

| ID | 질문 | 추천 초안 | 대안 |
| --- | --- | --- | --- |
| E1 | 24시간 동안 아무도 완료 확인하지 않으면? | ‘종료·확인 대기’로 남기고 알림. 자동으로 본인 확인/평가 권한/상대 후기 열람을 생성하지 않음 | 일정 보관함으로 자동 이동하되 본인 확인은 여전히 필요 |
| E2 | 한쪽만 완료 확인한 뒤 상대가 차단하면? | 연락은 즉시 차단. 기존 완료 확인·평가는 보존하고 동행은 이의 확인 상태, 후기 공개는 보류 | 미완료 동행으로 취소하되 제출 평가·이력은 보존·보류 |
| E3 | 같은 상대와 확정 동행이 여러 개일 때 차단하면? | 아직 완료되지 않은 해당 상대와의 동행 전체를 취소하고 영향 건수를 안내 | 이번 동행만 취소하면 나머지 약속이 연락 불가로 남으므로 별도 정리가 필요 |

E2는 **완료 확인 사실 하나를 다른 사람의 차단으로 삭제하거나, 취소 때문에 기존 평가가 사라지는 문제**를 막기 위해 필요한 판단이다. 이미 양쪽이 완료한 동행은 기존 명세대로 차단 시 취소하지 않는다. 실제 제재·당도 감점은 자동 실행하지 않는다.

## 명시적으로 보류한 논의

- 당도 합산·하한·갱신 시점: 사용자 요청대로 논의 필요. 현재 자동 계산 보류.
- 실제 인증·결제·통화·AI·운영 접수·데이터 보존은 이번 프론트 설계에서 실제 완료로 가장하지 않는다.
- 관심친구 정책은 통째 후속으로 미루지 않는다. FAVORITE-01~05를 사용자와 한 항목씩 검토한 뒤 상태·전이·화면에 반영한다.

전체 구현 인계는 위 질문의 답변 및 명시적 보류 범위를 함께 포함해야 한다.
