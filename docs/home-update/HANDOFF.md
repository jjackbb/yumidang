# 홈 프론트 수정 — 2026-09-14

대상: `jjackbb/yumidang6`, Vercel `yumidang6`. 사용자의 현재 범위는 프로토타입 프론트 수정이다.

## 반영 내용

- 로그인 팝업 상단 로그인/가입 탭 삭제. 하단 ‘휴대폰 본인인증으로 가입’에서 가입 단계로 전환하고 로그인으로 돌아갈 수 있다.
- 로그인·가입 전화번호는 숫자 최대 11자리. 형식이 있는 번호를 붙여넣으면 숫자만 추출한다.
- 헤더 알림은 종 하나. 홈의 신청 도착 박스 및 별도 사람 모양 신청함은 표시하지 않는다.
- Me 상단 ‘신청한 동행 / 받은 신청’ 탭에서 같은 페이지 내 목록을 전환한다. requesterId와 hostId로 구분하며 수락/거절은 받은 신청에만 있다.
- 종 알림의 신청 확인 버튼은 Me의 받은 신청 탭을 연다. 로그인 전이라면 로그인 후 그 위치로 돌아간다.
- 확정 약속을 배열로 관리한다. 새 매칭 수락 시 기존 약속을 유지하고 추가한다.
- 홈 리마인드는 한국 날짜 기준 D-day~D-7의 시작 전 확정 약속만, 가까운 순서로 표시한다. 여러 건은 가로 스크롤과 위치 바로 탐색한다.
- 홈 이벤트는 현재 주차에 시작하는 행사만 표시한다. 전체보기는 월/주차 필터와 가로 카드 목록이다. 스크롤 위치와 하단 바가 연동되며 바는 버튼이 아니다.
- 주차 기준: 1~7일=1주차, 8~14일=2주차, 15~21일=3주차, 22~28일=4주차, 나머지=5주차. 한국 시간 기준. 월요일 시작 주간 기준으로 바꾸려면 제품 판단이 필요하다.
- 지난 주차에 시작한 행사는 그 주차에서 조회한다. 종료일 당일까지 진행 중이며 다음 날 종료/회색 처리한다. 종료 상세도 열 수 있다.
- ‘지금’은 카테고리 왼쪽 첫 칸, 아이콘은 ‘당!’, 상세 제목은 ‘지금이당!’. ‘전체보기’ 카테고리는 ‘기타’로 바꾸고 기타 공고만 필터링한다.

## 이번 단계의 한계와 다음 구현

**실제 AI 크롤링·행사 자동 수집은 아직 구현하지 않았다.** 날짜 필터와 상태를 검증할 수 있는 예시 행사이며 화면에 ‘프로토타입 예시 행사’로 표시한다. 예시 행사는 실제 행사 안내나 예약 근거가 아니다.

다음 단계에서 수집 대상 공식 행사 출처와 대상 지역을 정하고, 서버의 주기 실행 → 수집 → 시작일/종료일 검증 → 중복 제거 → 저장 → 프론트 공급을 연결한다. 프론트 계약은 `startsOn`, `endsOn`(YYYY-MM-DD), `kind`, `sourceType`, `sourceUrl`, `description`이다. 진행 중 여부로 주차를 이동시키지 않는다. 수집 실패/오래된 데이터 안내와 출처별 검증도 필요하다.

휴대폰 인증·신청·수락·약속 데이터는 기존 프론트 시뮬레이션이다. 테스트용 로그인의 고정 사용자 ID로 보낸 신청 1건/받은 신청 2건을 체험한다. 새로고침 시 상태가 초기화된다. 실제 SMS 인증, 사용자 간 실시간 전달, DB 저장, 결제 검증의 완료를 의미하지 않는다.
