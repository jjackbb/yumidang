# 아침 확인 보고서

## 현재 결과

확정한 프론트 프로토타입 1~6단계를 구현했다. Claude가 완료한 공통 상태·가입·프로필·탐색·공고·Me 흐름 위에 GPT가 관심친구·초대·알림, 완료·평가·안전, 후속 기능 체험과 전체 시연을 연결했다.

최신 로컬 주소: http://127.0.0.1:4193/?demo=1

## 5분 시연 순서

1. 상단 **체험 설정**에서 `전체 · 가입부터`를 누른다. 헤더 **로그인** → `휴대폰 본인인증으로 가입`으로 들어가 전화번호 11자리 제한과 짧은 가입 단계를 본다.
2. 체험 설정에서 예시 회원 **조*미**로 전환한다. 홈에서 종 하나, 이번 주 이벤트, D-7 이내 약속 캐러셀, `당! 지금`, `기타`를 확인한다.
3. **Me → 초대 관리**에서 받은 초대를 본다. 기본 최신순에서는 내가 저장한 사람을 먼저 묶고, `시간순`에서는 관심친구 고정 없이 동행 시작이 빠른 순으로 바뀐다. 이름 옆 ★와 `동행한 적 있음` 표시도 확인한다.
4. 관심친구 목록에서 새 공고 알림을 사람별로 끄고, **알림 설정**에서 `처음 보는 사람의 초대 알림`을 끈다. 알림을 꺼도 받은 초대 목록이 유지되는지 본다.
5. 체험 설정에서 `완료·평가부터`를 누른다. 종료 전에는 완료가 잠기고, 종료 시각부터 **내 동행 완료 확인** → 즉시 평가가 열린다. 07 A/B를 바꿔 한 장 방식과 별점→후기 방식을 비교한다.
6. 상대 역할로 전환해 같은 동행의 평가를 제출한다. 한쪽만 제출했을 때 비공개이고 양쪽 제출 뒤 동시에 공개되는지 확인한다. 7일 자동 공개와 자동 당도 상승은 없다.
7. **Me → 안전·계정 설정**에서 동행 취소와 차단이 분리된 흐름, 차단 해제, 신고·이의제기·계정 제한·탈퇴 안내를 본다. E2/E3 복합 상황은 실행하지 않고 보류 이유를 보여준다.
8. **후속 기능 체험**에서 전화, PRO 결제, 캘린더, AI 탐색, 행사 수집을 각각 연다. AI 조건은 사용자가 수정해 탐색 목록에 적용할 수 있고, 어느 화면도 실제 외부 성공으로 표시하지 않는다.

## A/B 비교 위치

- **02 상대 프로필**: A 요약 후 펼치기 / B 전체 연속 보기
- **04 공고 작성**: A 한 장 / B 두 단계
- **07 평가**: A 한 장 / B 별점 후 후기

상단 체험 설정에서 바꿔도 같은 데이터가 유지된다.

## 구현된 핵심 흐름

- 관심친구는 동행 경험 없이 조용히 저장하며 저장 사실을 상대에게 알리지 않는다.
- 공개 공고 작성 → 관심친구 초대 → 상대의 직접 신청 → 작성자 최종 수락으로 확정된다.
- Me에서 보낸/받은 신청과 초대를 관리하고, 알림에서 정확한 공고로 이동한다.
- 개인별 완료 확인과 평가를 분리했다. 각자는 본인 완료 확인 직후 평가할 수 있다.
- 평가 작성 기한은 종료 뒤 7일 미만이며, 한쪽 미제출 후기는 계속 비공개다.
- 취소와 차단을 분리하고 완료 기록을 보존한다.
- 후속 기능은 기능별 입력·상태·실패/빈 화면이 있는 체험 앞단으로 구성했다.

## 아직 실제 연동이 아닌 것

- 실제 SMS와 본인인증
- 두 기기 사이의 데이터 동기화와 운영용 이전 외부 백엔드 정책 검증
- 실제 전화 연결, 결제·환불·정산, 외부 캘린더 쓰기
- 실제 AI 검색, 행사 크롤링과 출처 검수
- 운영 신고 접수·제재·탈퇴 처리
- Vercel 배포와 Gemini 독립 출시 검증

이전 외부 백엔드 DB·인증은 다른 대화 세션에서 작업 중이므로 이 보고서의 프론트 완료 판정과 분리한다.
