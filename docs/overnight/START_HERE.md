**현재 결과 (2026-09-15 16:25 KST): GPT가 프론트 프로토타입 1~6단계를 완료했다. [아침 확인 보고서](MORNING_REPORT.md)를 먼저 읽는다.** Claude 자동 실행 설명은 이전 실행 기록이며 현재 시작 명령이 아니다. 이전 외부 백엔드 DB·인증은 다른 대화 세션 담당이다.

승인일: 2026-09-15. 사용자: “이제 Claude opus5로 구현… MD파일로 할일… 한번에 알아서 단계별… 아침에 완성본”.
이 지시는 design-selection의 과거 “구현 미시작 / 답변 후 인계” 상태를 대체한다.

## 목표와 완료 기준

확정한 01~11, P1~P3, F01~F05, N1/N2/S1/S2를 **연결된 프론트 프로토타입**으로 완성한다.
가입 → 공고/상대 확인 → 신청 → 선택적 대화 → 작성자 수락 → 동행 종료 → 각자 완료 확인 → 평가까지 체험한다.
공개 API·DB 제품화나 실제 SMS·이메일 인증·결제·통화·행사 수집은 완료라고 주장하지 않는다.
실제 연동이 미정인 기능도 의미 있는 체험 앞단을 제공한다. 세부 디자인 통일은 후속 작업이며, 이번에는 기존 디자인을 활용해 읽기·조작·반응형 품질을 맞춘다.

## 이전 Claude 실행 기록

`python3 scripts/run-claude-overnight.py`

실행기는 기존 Claude 로그인으로 `claude-opus-5`만 사용한다. 다른 모델 자동 대체 없음.
단계마다 새 Claude 실행에 이 문서·SPEC·해당 TASK를 전달한다. 실패 시 결과를 전달해 같은 단계 수정, 통과 후 다음 단계.
세션 한도에 걸리면 응답에 표시된 초기화 시각에 1분 여유를 두고 재시도한다. 초기화 시각을 읽을 수 없는 일시 장애만 10분 간격으로 재시도한다. 실행당 8시간 상한은 유지하며, 검사 실패 수정은 단계당 최대 5회이다. 각 호출의 로그는 별도 파일로 보존한다.
일반 구현 선택은 스스로 처리한다. 중요한 미정 정책은 SPEC의 보류 방식으로 앞단만 구현하고 다른 작업을 계속한다.
체크리스트에 표시만 하는 것으로 끝내지 말고 실제 파일·작동 결과·검사 증거를 남긴다.
Claude가 작성한 단계 보고와 실행기가 직접 실행한 검사 결과를 구분한다.

## 범위와 보존

- 작업 폴더 이름은 yumidang5지만 실제 저장소는 jjackbb/yumidang6이다.
- 기존 사용자 변경·분석 원본·실패 증거를 보존한다. reset/clean/stash, 전체 파일 삭제 금지.
- 현재 앱 구현 담당은 GPT/Codex. Claude의 1~3단계 구현·검증 기록은 보존하고 4단계부터 이어받는다. DB·인증 작업과 공유 파일의 경계는 GPT_HANDOFF.md를 따른다.
- 변경 가능: src, tests, 필요한 package 설정, docs/overnight 결과 문서.
- 계약·할 일·합격 기준을 축소하거나 테스트를 지워 통과시키지 않는다.
- 비밀키·계정 파일·.git/.claude/전역 설정 변경, 외부 발송·운영 DB 쓰기 금지.
- 외부 API와 운영 서비스는 데모에서 호출하지 않는다. 이전 외부 백엔드 기존 연동 코드는 보존하되 명시적 데모에서는 격리한다.
- 이번 자동 실행 결과 확인은 로컬 브라우저가 기준이다. GitHub/Vercel 게시 성공을 수행 없이 기록하지 않는다.

정지: `kill -TERM $(cat .overnight/runner.pid)` (이 실행기와 직접 띄운 자식 프로세스만 종료).
