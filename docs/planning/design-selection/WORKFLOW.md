# 현재 작업 방식 — 초안 전체 선택 후 묶어서 구현

최종 지시: 2026-09-15. 이전 문서의 ‘한 흐름씩 바로 구현·배포’ 절차를 대체한다.

**현재 단계: 2026-09-15 사용자 요청으로 Claude 사용량 한도 이후 GPT 인수인계로 전환했다.** [확정 계약](../../overnight/SPEC.md) · [실행 상태](../../overnight/STATUS.md). Claude 1~3단계 결과를 보존하고 4~6단계를 이어받는다. 이전 외부 백엔드 DB 작업은 다른 세션 담당이다. 아래 이전의 선택 후 인계 절차는 선택 기록이다. 미정 초대·완료·차단 경계는 앞단/보류 범위로 유지하며 디자인 통일은 후속 작업이다.

## 역할과 진행 순서

노션 동기화 상태 (2026-09-15): FAVORITE-01~05와 CHAT-04의 관심친구 참조 메모 한 칸을 재정의했다. [관심친구 변경 기록](notion-favorite-sync.json). 이후 사용자 지시에 따라 이 재정의는 유지하고, N1/N2/S1/S2 및 연결된 F04/F05를 NOTI-01·MY-01·MY-02에 원문 보존 방식으로 추가했다. 추가한 10개 셀 내용만 ‘확정 추가’ 표시와 기울임꼴을 적용했으며, 재조회로 보존 범위와 서식을 검증했다. [추가 반영 기록](notion-additions-sync.json). 가입·완료·평가 등 그 외 변경은 아직 노션에 반영하지 않았다.

1. Codex: 기존 문서·구현을 바탕으로 여러 방법을 가벼운 스케치로 제시한다.
2. 사용자: 화면 방식과 중요한 정책을 선택한다. 추천·미응답·파일 생성은 승인으로 처리하지 않는다.
3. Codex: 전체 선택이 모이면 한 번의 구현 인계로 정리한다. 수정 메모의 의미가 충돌할 때만 필요한 판단을 묻는다.
4. 구현: 당초 10월 7일까지 Claude Opus 5로 지정했으나, 9월 15일 사용량 한도로 GPT가 이어받도록 사용자가 변경했다. Claude 자동 재시도는 종료했으며 확정한 화면·정책과 A/B 비교 범위는 그대로 유지한다.
5. 묶음 구현 안에서는 의존 순서대로 연결하고 적절한 검증을 한다. 매 작은 화면마다 사용자 선택·구현·배포를 반복하지 않는다.
6. 전체 기능 연결 후 디자인 결을 한 번에 맞춘다. 그 전에도 화면을 읽거나 조작할 수 없을 정도의 문제는 해결한다.

현재 완료 기준은 **남은 화면 방식 선택 + 정책 확정 또는 명시적 보류 + Claude가 실행할 단일 인계 묶음**이다. 사용자 1차 선택은 기록했다. 02·04·07은 두 안 비교 제작, 11은 두 체험 방식 모두 제공한다. 관심친구 정책과 완료 경계 사례는 최종 명세 전에 확인한다.

## 기준과 기존 구현

- 실제 메인 저장소: jjackbb/yumidang6. 로컬 폴더명 yumidang5는 그대로이다.
- 이 전환 시점의 기존 구현: 4033613. 홈 수정, 공고 상세→프로필, 신청→대화→작성자 수락, 조건 변경 재동의, 마감·만료·취소, 종료 시각 제한 등이 존재한다. 되돌리지 않는다.
- 사용자 확정: 작성자가 최종 수락하면 확정. 대화는 선택. 공고 종료 시각부터 완료 가능.
- 기존 구현 상세는 [기존 진행판](../prototype-roadmap/PLAN.md), [2차 인계](../../post-lifecycle/HANDOFF.md)에 보존한다. 구현 여부는 사용자 UX 승인과 다르다.
- 근거는 9/15에 조회한 [최신 MVP](https://app.notion.com/p/3db626093f2e80c89662e7104fad9795), [기능명세](https://app.notion.com/p/3d5626093f2e8031927bf5d680bebe67)와 기존 분석/구현 기록이다. OLD DATA_참조x와 하위 페이지를 참조하지 않는다.
- 현재 자료를 바탕으로 식별한 항목을 모았다. 전체 서비스의 서버·운영 요구까지 새로 검증했다는 의미는 아니다.

## 아직 확정하지 않은 규칙

- P1 완료 주체는 확정: 각자 완료 확인 직후 자신의 평가 가능. 본인 완료 확인·평가 제출 후 상대 평가 열람. 종료 후 7일까지 작성, 양쪽 제출 시 공개. **7일 뒤 자동 공개 삭제.** 자동 완료·이의제기 경계는 확인 필요.
- P2는 A로 확정: 실제 자동 점수 계산 보류. **합산·하한·갱신 시점은 논의 필요.** 신규 15와 문서의 점수 요소를 임의로 바꾸지 않는다.
- P3는 차단과 취소 두 버튼: 동행 취소만 가능, 차단하면 동행도 취소. 한쪽만 완료 확인한 때·동일 상대와 복수 동행은 추가 판단.
- 관심친구 선택: 누구나 비공개 저장, 공개 공고 작성 후 초대, 직접 신청 후 작성자 수락. 알림 바로가기+Me 관리, 최신 초대순에서만 수신자의 관심친구 우선. 저장 해제로 초대·신청·동행은 취소하지 않음. N1 A: 저장 시 새 공고 알림 기본 켜짐. N2 B: 모든 초대를 기본 알리고, Me에서 처음 보는 사람의 초대 ‘알림’ 하나로 조절. S1 최신 수정: 기본 최신 초대순에서는 관심친구 우선, 시간순은 고정 없이 전체 시작 시각순. 이름 옆 관심친구 ★/이전 동행 표시, 처음은 표시 없음. S2 A: 저장하지 않았고 동행 경험 없는 사람. 24시간·하루 3건·주 10건·6시간 우선 공개·30일 보관함은 미채택.
- 취소 페널티, 노쇼 판정·점수, 탈퇴/운영 보존 정책은 이번 초안에서 실제 실행 규칙으로 확정하지 않는다. 기능이 미정이면 해당 버튼·상태 예시를 제공하되 감점·제재·외부 접수가 실제 완료됐다고 쓰지 않는다.
- 기존 경고 후 진행하는 일정 중복 처리 등은 구현 현황이다. 사용자 승인 정책으로 승격하지 않으며 변경 의견을 받을 수 있다.
- 행사 주차는 현재 1~7일/8~14일 방식이다. 달력 주간으로 바꾸는 선택은 아직 없으므로 스케치 단계에서 조용히 바꾸지 않는다.
- 실제 인증·통화·결제·AI 수집·운영 서버는 이번 화면 선택과 구분한다. 신고·차단 UI 자체를 후속 기능으로 일괄 제외하지 않는다.

## 선택 후 Claude에 전달할 묶음

사용자가 답을 보내면 선택/수정/보류를 기록하고, 다음 내용을 하나의 인계 파일로 정리한다.

- 선택한 화면 구조와 유지할 기존 연결.
- 화면별 진입·성공·실패·빈 상태·권한·종료/취소 상태와 뒤로가기.
- 공고/신청/대화/동행/평가/알림이 공유할 식별자와 상태 전환.
- 프론트 예시와 실제 연동의 경계, 새로고침/탭 이동의 데이터 보존 기대.
- 작업 파일과 의존 순서, 검증 시나리오, 완료 기준.
- 미결정 정책은 실행 가능한 정책으로 채우지 않고 앞단 예시 또는 명시적 보류로 남긴다.

선택판의 브라우저 저장은 사용자 편의를 위한 로컬 기록이다. 워크스페이스의 승인 기록으로 자동 반영되지 않는다. 복사한 선택 내용이나 사용자의 대화 답변을 받은 뒤 확정 상태를 갱신한다.
