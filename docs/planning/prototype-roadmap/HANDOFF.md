# 신청·대화 연결 인수인계 — 2026-09-15

이 문서는 1차 구현 기록이다. 이후 [2차 공고 변경·종료 연결](../../post-lifecycle/HANDOFF.md)을 반영했다. 현재 작업은 [남은 초안 전체 선택](../design-selection/SKETCHES.html)이며, 사용자 선택 후 Codex가 설계하고 Claude가 묶음 구현하는 [최신 작업 기준](../design-selection/WORKFLOW.md)을 따른다.

## 결정과 구현

사용자가 작성자 최종 수락 즉시 확정을 선택했다. 노션 MVP와 기능명세의 최신 내용을 다시 확인했고 `OLD DATA_참조x`는 읽지 않았다. [PLAN](PLAN.md)에 나머지 판단과 후속 작업을 구분했다.

- 신청마다 `requestId → roomId → appointmentId`를 연결한다. 신청 시 채팅 가능, 작성자 수락 시 같은 방에 확정 약속을 연결한다.
- 메시지·초안·일정 제안은 App 공통 상태에 보관한다. 다른 방이나 하단 탭으로 이동해도 해당 세션 동안 보존된다.
- Me의 신청 목록, 상대 프로필, 공고, 알림, 약속 상세에서 동일한 대상에 접근한다. 비회원이나 방의 참여자가 아닌 사용자는 채팅을 볼 수 없다.
- 작성자만 수락/거절, 신청자만 확정 전 취소. 한 공고의 한 신청만 확정하고 나머지는 `matched_with_other`. 중복 수락을 막는다.
- 취소·거절·다른 후보 확정은 종료 사유를 표시하고 과거 대화만 열어둔다. 공고 마감/만료/삭제에 대한 방의 읽기 전용 판정도 포함한다. Me의 세부 종료 상태 동기화는 2차 과제다.
- 신청자 체험 계정에만 ‘작성자 수락 시연’ 도구를 표시한다. 자동 상대 답장/자동 제안 수락은 없앴다. 실제 상대 응답으로 위장하지 않는다.
- 일정 제안은 응답 전까지 기존 약속을 유지한다. 명시적으로 수락했을 때 연결된 약속과 공고만 변경한다.
- 완료/평가 콜백은 각 방의 약속을 직접 받는다. 다른 약속 대시보드를 보다가 돌아와도 잘못된 약속에 완료나 평가가 적용되지 않는다.
- 통화·PRO 결제는 준비 중 안내와 구성 미리보기로 유지한다. 결제 화면에서 자동 매칭되던 경로를 없앴고 Me의 결제 내역도 예시라고 표시했다.

## 경계와 다음 순서

프론트 시뮬레이션이다. 서버 메시지/신청 저장, 실제 계정 간 실시간 수신, 서버 권한·원자적 매칭 검증, 새로고침 보존은 미구현이다. 브라우저 검증은 이전 외부 백엔드 요청을 가로채 외부 쓰기를 하지 않았다. 실제 사용자 검증으로 해석하지 않는다.

다음은 2차: 모집 마감·만료·삭제와 Me 신청 상태 동기화, 공고 조건 변경 재확인, 확정 동행 취소, 시간 충돌 안내. 3분 체험 범위 및 완료 권한·당도 정책은 해당 단계에서 사용자와 결정한다. 캘린더 등 남은 후속 UI도 [PLAN](PLAN.md)에 남겼다.

- 모바일 390×844 및 데스크톱 1280×844. 사용자 동작 시나리오와 화면 증거는 [evidence](evidence), 진행판 동작은 [board-check.json](evidence/board-check.json).
