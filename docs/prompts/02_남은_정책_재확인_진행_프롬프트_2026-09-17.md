### 3. 한 질문을 설명하는 형식

각 질문은 아래 형식을 지키세요.

#### Q번호와 쉬운 제목

1. **왜 지금 결정해야 하는가**
   - 어떤 사용자 흐름과 연결되는지 쉬운 말로 설명합니다.
   - 이미 구현된 동작, 아직 없는 정책, 운영자가 해야 할 일을 구분합니다.
2. **상황 예시**
   - 정상 상황 1개와 문제·악용·예외 상황 1개를 구체적으로 서술합니다.
   - 관련될 때 작성자·신청자·운영자 각각 무엇을 보고 무엇을 할 수 있는지 설명합니다.
3. **추천안**
   - 추천 결론을 먼저 말하고 이유를 설명합니다.
   - 사용자 편의, 안전, 악용 가능성, 개인정보, 운영 부담, 구현 복잡도 중 관련된 영향을 함께 적습니다.
   - 추천안의 단점과 어떤 증거가 나오면 추천을 바꿀지도 적습니다.
4. **대안 1**
   - 추천안과 실질적으로 다른 선택이어야 합니다.
   - 장점·단점·필요한 운영을 설명합니다.
5. **대안 2**
   - 추천안과 대안 1의 말만 바꾼 안이 아니라 다른 기준의 선택이어야 합니다.
   - `이번 MVP에서는 보류하고 수동 운영`이 타당한 경우 하나의 대안으로 사용할 수 있습니다.
6. **선택하면 실제로 달라지는 것**
   - 화면 문구와 버튼
   - 알림 시점
   - 저장해야 할 상태·기록
   - 권한과 개인정보 노출
   - 운영자 처리와 분쟁 가능성
   위 항목 중 관련된 것만 구체적으로 적습니다. 확정 DB 컬럼처럼 단정하지 않습니다.
7. **사용자 선택**
   - `추천안 / 대안 1 / 대안 2 / 보류 / 직접 의견` 중 고르게 합니다.
   - 숫자·기간·횟수가 필요한 질문은 추천 근거가 약하면 억지 숫자를 제시하지 말고 `관찰 후 결정` 대안을 포함합니다.

### 4. 대화 진행 규칙

- 한 번에 최대 3개 질문만 설명하고 답을 기다리세요.
- 앞선 답이 다음 질문에 영향을 주면 먼저 연결 관계를 알려주세요.
- 사용자가 이유 없이 번호만 선택해도 선택 자체는 기록하되, 서로 충돌할 때만 이유를 짧게 확인하세요.

- 어려운 법률·개인정보 판단은 적법하다고 단정하지 말고 검토 필요 상태로 남기세요.

- 특정 결론으로 유도하지 마세요. 다만 추천은 숨기지 말고 근거와 한계를 분명히 제시하세요.
