#### Q번호와 쉬운 제목

1. **왜 지금 결정해야 하는가**
   - 어떤 사용자 흐름과 연결되는지 쉬운 말로 설명합니다.
   - 이미 구현된 동작, 아직 없는 정책, 운영자가 해야 할 일을 구분합니다.
2. **상황 예시**
   - 정상 상황 1개와 문제·악용·예외 상황 1개를 구체적으로 서술합니다.
   - 관련될 때 작성자·신청자·운영자 각각 무엇을 보고 무엇을 할 수 있는지 설명합니다.
3. **추천안**
   - 추천 결론을 먼저 말하고 이유를 설명합니다.
   - 사용자 편의, 안전, 악용 가능성, 개인정보, 운영 부담, 구현 복잡도 중 관련된 영향을 함께 적습니다.
   - 추천안의 단점과 어떤 증거가 나오면 추천을 바꿀지도 적습니다.
4. **대안 1**
   - 추천안과 실질적으로 다른 선택이어야 합니다.
   - 장점·단점·필요한 운영을 설명합니다.
5. **대안 2**
   - 추천안과 대안 1의 말만 바꾼 안이 아니라 다른 기준의 선택이어야 합니다.
   - `이번 MVP에서는 보류하고 수동 운영`이 타당한 경우 하나의 대안으로 사용할 수 있습니다.
6. **선택하면 실제로 달라지는 것**
   - 화면 문구와 버튼
   - 알림 시점
   - 저장해야 할 상태·기록
   - 권한과 개인정보 노출
   - 운영자 처리와 분쟁 가능성
   위 항목 중 관련된 것만 구체적으로 적습니다. 확정 DB 컬럼처럼 단정하지 않습니다.
7. **사용자 선택**
   - `추천안 / 대안 1 / 대안 2 / 보류 / 직접 의견` 중 고르게 합니다.
   - 숫자·기간·횟수가 필요한 질문은 추천 근거가 약하면 억지 숫자를 제시하지 말고 `관찰 후 결정` 대안을 포함합니다.

#### 7-1. 화면 정리 중 발견한 것 (결정 필요)

1. **누르면 "준비 중"만 뜨는 기능이 많다.** 신고, 차단, 초대, 관심친구, 공고 수정·마감·삭제, 확정 동행 취소, KYC, 유료 결제, 안심 통화가 해당한다. UT에서 느낀 혼란의 원인일 수 있으므로 기능별로 `숨김 / 준비 중으로 표시 / 이번에 구현` 중 결정이 필요하다. 결정 전까지 Stitch 시안에서는 빼고, 코드에서도 지우지 않는다.
2. **신고 화면 문구가 서로 충돌한다.** 신고 화면(ReportModal)은 "운영팀에서 실시간 확인 후 계정 조치 및 당도 감점 처리가 진행됩니다"라고 안내하지만, 신고 후 알림은 "실제 운영팀·기관에 전달되지 않았고 자동 제재나 당도 감점도 없어요"라고 한다. 신고 정책(처리 주체·제재·당도 반영)을 정한 뒤 한쪽으로 통일한다.
3. **마이 화면의 에스크로 탭**은 실서비스에서도 예시 결제 데이터를 항상 보여준다. 숨길지, 준비 중으로 남길지 결정한다.
