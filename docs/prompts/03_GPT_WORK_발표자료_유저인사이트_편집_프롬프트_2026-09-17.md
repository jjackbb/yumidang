# GPT Work 발표자료 유저 인사이트 편집 프롬프트

## 사용 방법

1. GPT Work 새 대화에 기존 10페이지 PPTX를 첨부한다.
2. Presentations 기능을 사용할 수 있다면 `@Presentations`와 함께 아래 프롬프트 전체를 붙여 넣는다.
3. 결과로 받은 PPTX의 7~10페이지와 발표자 노트를 직접 확인한다.

## 복사용 프롬프트

```text
@Presentations

첨부한 PPTX는 내일 발표할 유미당 서비스 발표자료입니다. 총 10페이지 중 1~6페이지는 이미 완성됐고, 7~10페이지에 유저테스트 인사이트를 넣으면 완성됩니다.

먼저 전체 10페이지를 읽어 발표의 대상, 이야기 흐름, 슬라이드 크기, 레이아웃, 글꼴, 색상, 도형, 아이콘, 로고와 문장 톤을 파악하세요. 그다음 1~6페이지는 내용과 디자인을 변경하지 말고, 7~10페이지만 아래 내용으로 완성하세요. 전체 슬라이드 수는 반드시 10페이지로 유지하고 새 슬라이드를 추가하지 마세요.

발표 대상은 강사·팀원·서비스 기획 평가자이며, 목적은 “유저테스트를 통해 무엇을 발견했고 제품 방향을 어떻게 바꿨는가”를 짧고 설득력 있게 보여주는 것입니다.

## 공통 편집 원칙

- 1~6페이지의 시각 언어를 그대로 따르세요. 새로운 테마나 별도 디자인 시스템을 만들지 마세요.
- 7~10페이지에 기존 레이아웃이나 유용한 요소가 있으면 재사용하고, 아래 메시지에 맞게 내용만 재구성하세요.
- 각 페이지는 핵심 메시지 하나만 전달하고, 제목만 읽어도 결론이 이어지게 만드세요.
- 긴 문단을 피하고 카드, 흐름도, 우선순위 표처럼 한눈에 읽히는 시각 구조를 사용하세요.
- 글자가 작아지지 않게 내용을 줄이세요. 발표자가 읽을 원고를 본문에 모두 넣지 마세요.
- 모든 텍스트·도형·표는 PowerPoint에서 편집 가능한 상태로 유지하세요. 슬라이드를 통이미지로 만들지 마세요.
- 사용자 얼굴 사진, 가짜 인터뷰 사진, 근거 없는 통계, 가상의 직접 인용문은 만들지 마세요.
- 아래 숫자와 관찰만 사용하고, 작은 표본을 전체 시장의 통계처럼 표현하지 마세요.
- 슬라이드마다 30~45초 분량의 발표자 노트를 추가하세요. 노트는 쉬운 한국어 구어체로 작성하세요.

## 7페이지 — 유저테스트 개요

권장 제목:
“6명의 사용자는 실제로 동행이 필요했던 순간이 있었다”

반드시 포함할 내용:

- 2026년 9월 16일, 사용자 6명 대상 정성 유저테스트
- 확인 흐름: 동행 필요 경험 → 공고 탐색 → 상세 확인 → 상대 프로필 → 신뢰 판단 → 신청 → 대화 → 최종 결정
- 6명 모두 친구나 지인을 구하지 못해 하고 싶은 활동을 포기하거나 혼자 해결했던 경험이 있었음
- 예시: 팝업 방문 포기, 불꽃축제를 집에서 봄, 맛집 대신 배달, 2인 예매 비용을 혼자 부담
- 하단에 작은 문구: “정성 테스트 6명의 관찰 결과이며 시장 전체를 대표하는 통계는 아님”

권장 시각화:

- 가운데에 8단계 사용자 여정
- 아래 또는 옆에 실제 경험 예시 3~4개를 짧은 카드로 표시

이 페이지의 결론:
“동행 필요성은 있었지만, 낯선 사람과 만날 만큼 안심할 근거가 부족했다.”

## 8페이지 — 핵심 인사이트 3가지

권장 제목:
“사용자는 사람을 고르기보다, 안심하고 결정할 근거를 찾았다”

세 개의 카드 또는 세로 영역으로 구성하세요.

### 인사이트 1. 기본 조건은 목록에서 바로 확인

- 목적·시간·장소·성별·나이는 공고 선택의 첫 판단 기준
- 최소 5명이 성별을 명확한 판단 정보로 확인
- 현재는 일부 정보가 상세나 프로필 안에 숨어 있어 반복 이동이 발생

짧은 결론:
“핵심 조건은 공고 목록에서 비교할 수 있어야 한다.”

### 인사이트 2. 자기소개보다 검증된 신뢰 정보

- 사용자는 인증 상태, 동행 이력, 후기, 당도의 의미를 확인하려 함
- 직접 작성할 수 있는 소개만으로는 신뢰 판단이 충분하지 않았음
- 직장 인증을 해도 무엇이 달라졌는지 보이지 않고, 당도 기준도 이해하기 어려웠음

짧은 결론:
“정보의 양보다 검증 여부와 의미 설명이 중요하다.”

### 인사이트 3. 최종 확신은 대화에서 형성

- 6명 모두 대화가 상대의 취향·관심사·실제 사람이라는 느낌을 파악하는 데 도움이 된다고 응답
- 프로필만으로 결정하기보다 짧은 대화 후 동행 의사가 높아짐
- 하지만 처음 말을 거는 과정은 부담스럽고 소모적으로 느껴질 수 있음

짧은 결론:
“채팅은 부가기능이 아니라 최종 결정을 돕는 핵심 단계다.”

## 9페이지 — 발견된 불편과 개선 우선순위

권장 제목:
“먼저 신뢰를 깨는 오류를 고치고, 그다음 판단 정보를 개선한다”

P0·P1·P2의 3단 우선순위 구조로 표현하세요. 모든 세부 항목을 나열하지 말고 아래 핵심만 사용하세요.

### P0. 핵심 흐름 오류

- 신청 알림 누락
- 종료 시간이 시작 시간보다 앞설 수 있음
- 등록 후 내가 작성한 공고를 찾기 어려움
- 양쪽이 평가해도 ‘상대 평가 대기 중’으로 남는 오류
- 날짜가 시스템 형식으로 노출됨
- 실제로 없는 긴급 SOS 기능 안내

### P1. 참여 판단 정보

- 목록·상세·채팅의 성별·연령대 표시 일관화
- 성별·연령대 필터
- 인증 상태·후기·동행 이력·당도 설명
- 동행 확정 상태의 가시성
- 채팅 추천 인사말

### P2. 화면 이해와 입력 편의

- 너무 많은 버튼의 우선순위 정리
- 의미가 불명확한 ‘U’와 한글·영어 혼용 개선
- 뒤로가기·팝업 닫기 동작
- 날짜·시간·주소 입력과 단계식 공고 등록

권장 시각화:

- 위에서 아래로 `P0 즉시 수정 → P1 참여 판단 개선 → P2 사용성 정리`
- P0를 가장 강하게 강조하되 전체 디자인 색상 체계를 유지

## 10페이지 — 제품 방향과 다음 검증

권장 제목:
“유미당의 방향: 풍부한 프로필보다 검증된 정보와 짧은 대화”

가운데에 다음 흐름을 크게 보여주세요.

`기본 조건 빠른 확인 → 검증된 신뢰 정보 → 부담 없는 첫 대화 → 동행 확정`

하단에는 두 영역을 배치하세요.

### 바로 개선

- 핵심 오류와 잘못된 안내 수정
- 성별·연령대 등 판단 정보의 위치 통일
- 인증·당도·후기의 의미 설명
- 추천 인사말로 첫 대화 부담 감소

### 추가 검증 후 결정

- Instagram 연결, MBTI·성향 테스트
- 페널티 공개, 평균 응답 시간
- 채팅 이미지, 초대 제한, AI 검색
- 카테고리 확대와 업체 제휴

마지막 한 줄:
“다음 테스트에서는 핵심 정보를 찾는 시간, 신청 완료 여부, 대화 후 결정 변화를 다시 확인한다.”
```
