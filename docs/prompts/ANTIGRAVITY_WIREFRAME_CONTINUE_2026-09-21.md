# 안티그래비티 전달용 — 기존 HTML의 후속 수정

작성: 2026-09-21. 목적: 이번 주 포트폴리오 준비를 위해 Claude의 기존 결과를 이어받아 와이어프레임을 수정한다. 이 문서는 이관 준비이며 안티그래비티 실행 완료 기록이 아니다.

## 담당과 수정 범위

너는 유미당 와이어프레임의 **후속 수정 담당**이다. 검수만 하는 역할이 아니다. 사용자와 주 설계 담당 GPT가 핵심 구조·정책을 판단하고, 너는 사용자가 지정한 화면의 배치·문구·상태·모형 상호작용을 수정한다.

- 수정할 파일: `docs/planning/design/yumidang-wireframes.html`
- 결과를 누적할 파일: `docs/handoffs/화면구조_와이어프레임_HTML_2026-09-20.md`

## 처음 읽을 것 — 한 번만

1. 기존 HTML 인수인계의 **3차·4차 수정, 정책 확인 사항, NOT_RUN**을 먼저 읽는다. 이후 차수가 추가돼 있으면 더 최신 기록을 우선한다.
2. HTML의 스타일·공통 컴포넌트·해당 화면·이벤트 연결 위치를 검색해 구조를 파악한다. 현재 파일은 약 2,658줄이며 이후 달라질 수 있다. 전체 파일을 반복 출력하거나 재작성하지 않는다.
3. 필요한 화면만 `docs/planning/design/SCREEN_INVENTORY.md`, `docs/planning/design/DESIGN.md`와 대조한다.
4. 정책·API 쟁점이 있을 때만 `docs/work-allocation/01_POLICY_HANDOFF.md`, `02_API_HANDOFF.md`의 관련 항목을 읽는다.

`CLAUDE_WIREFRAME_REVISION_2026-09-20.md`는 초기 변경 근거다. 그 목록을 새 작업처럼 전부 재실행하면 3·4차 수정을 되돌릴 수 있다. 현재 사용자 지시가 가장 우선이며, HTML의 구현·과거 AI 인수인계만으로 미정 정책을 확정하지 않는다.

## 현재까지 이어받을 상태

다음은 **Claude 인수인계 기록 기준**이다. 실제 모형 동작·검증 결과와 구분해 필요한 부분만 확인한다. GPT가 이번에 브라우저 검사를 재실행한 결과가 아니다.

- S01: 공고 카드 시안 E, `등록일 순 / 시작일 순` 표시 전환, 필터 열린 화면, 작성자 나이 19~99 범위 바, 비로그인 날짜·성별·나이 필터 제한.
- S02: 우측 상단 수정·닫기, 작성자 상태 액션 시트, 신청자 선택, 확정 당사자/제3자 구분, 문구·버튼 배치 수정.
- S08: 한 줄 프로필, 일정 중복 경고와 신청 성공·실패 팝업 수정.
- S10: 사진 확대, 이름 옆 공고 제목, 상대 시각 표기.
- 익명 별칭과 사진·성별/나이의 모자이크 **표현 시안**이 있다. 실제 개인정보 비노출이나 신원 확인 기능으로 간주하지 않는다.
- 정렬은 현재 **라벨 전환만**, 나이 범위 바는 **고정 예시 표시**라고 기록돼 있다. 기존 기능을 실동작 완료로 보고하지 않는다. 사용자 요청에 필요하면 가벼운 모형 동작만 연결하고, 필요하지 않으면 미구현 상태를 유지·기록한다.
- 실제 API-08, 실기기, 접근성 검사는 미실행이다. 과거 PASS는 해당 차수의 기록이며 현재 검증으로 복사하지 않는다.

## 반드시 남길 결정 대기

- ‘마감’과 ‘확정’이 모두 신청자 선택→확정으로 이어지는 현재 모형의 의미는 미정이다. 모집 종료와 동행 확정을 임의로 합치지 않는다. 사용자+GPT와 팀원 1에 문제를 남기고 관련 없는 수정은 진행한다.
- 최종 확정 시 양쪽 일정 중복 차단은 기존 **D06 확정**이다. 새 미정 정책으로 다시 묻지 않는다. 경합 시 처리·알림 대상과 문구는 별도 확인 대상이다.
- 카드 본문은 S02, 우측 화살표는 S14로 연결하는 최신 배치를 보존한다. 타인 프로필은 로그인 조건을 유지한다.
- 비로그인 필터 제한·사진/행사 공개 범위·확정 제3자 정보는 팀원 1의 후속 회신과 맞춘다. 사진 모자이크를 안전한 익명화 완료로 표현하지 않는다.
- 기본 당도 `15당`, 정확한 장소의 작성자/확정 상대 권한, 신청과 최종 확정의 구분을 유지한다. 레퍼런스의 온도 표기를 근거로 당도 정책을 다시 바꾸지 않는다.
- 4차 기록상 비교안에도 연결 행사가 표시된다. 초기 프롬프트의 ‘비로그인 행사 숨김 비교안’을 최신 사용자 수정처럼 자동 복원하지 않는다. 최종 공개 정책은 대기다.
- 필터 하한 19세와 신청 조건 하한 18/19 논점은 다른 입력이다. 나이 필터를 수정하면서 신청 자격·가입 연령을 바꾸지 않는다.

## 적은 반복으로 작업하는 방식

1. 사용자에게 받은 수정 목록을 화면·공통 컴포넌트 기준으로 묶고, 이미 반영된 항목은 건너뛴다. 한 흐름 또는 관련 화면 1~3개씩 수정한다.
2. 여백·크기·정렬·줄바꿈 등 작은 변경은 바로 적용한다. 기능·권한·핵심 동선 변경은 기존 승인 범위를 확인한다. 자료에 없는 새 핵심 선택만 짧게 질문한다.
3. 매번 새 계획서·24개 전체 리뷰·전체 코드 재출력을 만들지 않는다. 필요한 주변 코드와 이번 diff를 중심으로 확인한다. 단일 파일 분할이나 프레임워크 도입을 시작하지 않는다.
4. 기본 산출물은 낮은 상세 수준의 와이어프레임이다. 장식·애니메이션·미세 픽셀 조정은 사용자 요청이나 가독성 문제에 필요한 만큼만 한다.
5. 수정 완료 후 해당 화면과 바뀐 상태를 브라우저에서 확인한다. 공통 카드·공통 스타일을 바꿨다면 그 요소를 쓰는 관련 화면을 추가 확인한다. 상태 전환이면 연결된 앞뒤 화면을 확인한다.
6. 변경하지 않은 24개 화면×모든 상태×모든 역할 검사를 매번 반복하지 않는다. 공통 렌더러처럼 영향이 전체에 미칠 때만 넓힌다. 실패를 고친 뒤 관련 범위만 다시 확인한다. 검사 도구가 없으면 NOT_RUN으로 남긴다.
7. 별도 테스트 프레임워크를 만들지 않는다. 캡처는 사용자가 검토할 변경 화면 위주로 남기며 같은 화면을 이유 없이 반복 촬영하지 않는다.
8. 완료 보고는 `바꾼 것 / 확인한 것 / 남은 결정`을 짧게 적는다. HTML 전체를 대화에 붙이지 않는다.

## 기록과 다음 작업

기존 HTML 인수인계에 실제 다음 차수·날짜로 수정 항목, 사용자 요구와 제안의 차이, 실행한 확인, NOT_RUN을 덧붙인다. 과거 기록을 지우거나 자신의 검증처럼 고쳐 쓰지 않는다.

정책·API 영향은 `발견 / 관련 화면 / ANON·UX·API ID / 사용자 확정 또는 제안 / 결정 대기 / 필요한 응답·권한`으로 남긴다. **주 설계 담당 GPT가 팀원 1·2 인수인계에 통합**하므로 동시에 그 공용 문서를 고치지 않는다.

사용자가 이번 메시지에 붙인 수정 목록부터 실행한다. 새 목록이 없다면 인수 준비를 마치고 현재 상태와 남은 결정만 짧게 알려준다. 남은 24개 화면을 임의로 전면 개편하거나 과거 수정 목록을 처음부터 재실행하지 않는다.
