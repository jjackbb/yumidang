# 유미당 작업 분담 — 2026-09-20

## 이번 목표와 결정

사용자 확정: **팀이 합의할 전체 화면 구조를 만든다.** 사용자와 현재 GPT/Codex가 핵심 구조·흐름·화면의 판단 기준을 설계한다. 팀원 1은 정책 재확인·충돌 정리, 팀원 2는 API 키 발급·연동 준비와 적용을 담당한다. Google Stitch와 Figma로 와이어프레임을 만든다.

이번 산출물은 담당자에게 전달할 작업 문서와 화면 구조 초안이다. 앱 구현·원격 설정·배포·불필요 파일 삭제를 실행한 것이 아니다. 앞선 정리 후보는 삭제 승인으로 바꾸지 않는다.

## 계정·도구 배분 제안

사용자 보유: GPT Pro, GPT Plus, Claude Pro, Gemini Pro 각 1개. 아래는 작업 배분 제안이며 계정의 실제 모델·잔여량·연결 상태를 확인한 결과나 성능 순위가 아니다. 팀원에게 개인 계정 자격증명을 공유하는 배분도 아니다. 각 담당자가 접근 가능한 도구로 같은 작업 문서를 사용한다.

| 도구 | 맡길 작업 | 넘기지 않을 판단 |
|---|---|---|
| GPT Pro / 현재 GPT·Codex 세션 | 전체 정보 구조, 핵심 흐름, 화면별 상태·권한, 정책/API 결과 통합, 최종 설계 검토 | 사용자·팀의 정책 선택을 대신 확정하지 않음 |
| GPT Plus | 팀원 1의 질문 정리, 선택지 비교, 회의 결과를 결정표로 변환 | 미응답을 승인하거나 확정 결정 재투표 금지 |
| Claude Pro | 팀원 2의 공식 문서 조사, 기존 코드 대조, 연동 코드·오류 처리·검증 준비. 구현 단계에 맡길 때 동일 담당 유지 가능 | 공급자·유료 범위·공개 정보 확대를 임의 결정하지 않음 |
| Gemini Pro | 화면 목록과 시안을 대조해 빠진 상태·흐름·문구 찾기, 같은 입력으로 시안 변형 보조 | 새 화면·정책을 승인본에 자동 추가하지 않음 |
| Google Stitch | 합의된 화면 설명으로 시각적 대안 생성 | 생성 결과를 제품 명세나 동작 검증으로 간주하지 않음 |
| Figma | 팀이 검토할 기준 화면, 상태별 변형, 클릭 흐름, 코멘트와 결정 기록 | 보기 좋은 시안을 팀 합의 완료로 간주하지 않음 |

GPT/Codex가 문서·코드를 직접 다루는지, 웹 채팅만 쓰는지는 현재 환경에 따라 다르다. 웹 채팅 담당에게는 파일 본문/첨부를 전달한다. 서로 다른 계정의 대화·파일이 자동 동기화된다고 가정하지 않는다. Stitch→Figma 이동 방법도 실제 계정에서 지원되는 경로를 확인하며 자동 변환을 전제로 하지 않는다.

## 충돌 없이 진행하는 순서

1. **전달 예정(2026-09-21):** 팀원 1·2에게 각 문서와 참조 자료를 전달해 작업을 시작한다. 9월 20일에는 폴더 정리·커밋/푸시를 먼저 마무리한다. 현재 GPT는 이후 전체 화면 목록을 사용자와 검토한다.
2. **첫 합류:** 팀원 1은 화면을 바꾸는 핵심 쟁점부터 회신하고, 팀원 2는 키를 받기 전에도 공급자별 가능한 필드·빈값·오류 예시를 회신한다.
3. **구조 합의:** 전체 화면의 유지/통합/추가 후보와 진입 경로를 표시한다. 정책 대기 영역은 해당 부분만 표시하고 다른 화면 설계를 계속한다.
4. **시안:** 한 흐름씩 Stitch에 입력한다. 선택한 결과는 Figma에서 같은 화면 ID로 정리한다. 앱 코드에 자동 적용하지 않는다.
5. **팀 검토:** 화면마다 정상·빈 상태·오류·권한 제한을 점검하고 결정/보류를 기록한다. 실제 사용성 검증은 별도 과업이며 이번 합의 완료와 구분한다.

공용 파일을 동시에 수정하지 않는다. 팀원 1의 새 결과는 `docs/product-decisions/TEAM1_RESULTS.md`, 팀원 2의 새 결과는 `docs/api-integration/TEAM2_RESULTS.md`에 남기는 것을 제안한다(아직 결과 파일 없음). 현재 GPT가 결과를 검토해 화면 목록과 공용 시작 문서에 반영한다. 기존 결정 원문은 보존한다. 코드 적용 시에는 담당 파일·브랜치를 먼저 나누고 공용 `App.tsx`·타입·migration 변경은 통합 담당과 맞춘다.

## 화면 합의 완료 기준

- 각 주요 과업이 어디서 시작하고 어디로 끝나는지 팀이 설명할 수 있다.
- 화면 ID, 이용자 권한, 주요 행동, 성공/실패/빈 상태가 표시돼 있다.
- 확정·설계 제안·정책 대기·API 확인 대기를 구분한다.
- 새 정책을 가정해야 하는 화면을 조용히 확정하지 않는다.
- 팀원 1·2의 결과가 어떤 화면을 바꾸는지 추적할 수 있다.

## 구독과 API 비용

보유 구독을 앱의 API 무료 이용권으로 계산하지 않는다. Codex 공식 안내는 구독 사용과 API 키 사용 과금을 구분한다. Claude Pro도 API 사용을 포함하지 않으며, Gemini API는 자체 프로젝트·무료/유료 구간과 결제 체계를 확인해야 한다. 발급·결제·호출 한도는 팀원 2가 각 계정에서 확인한다. Stitch/Figma의 실제 사용 가능 기능·한도도 별도로 확인한다.
